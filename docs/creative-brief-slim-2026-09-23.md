# 创意简报瘦身：creative_brief/2.0（2026-09-23）

简报从 14 个字段收成两项：`storyEngine`（原片的驱动结构，含观众对人物关系理解的 before/after）与
`recastTest`（换一个性格完全不同的角色，逐场问还成立吗）。其余内容由下游直接从原片分析与脚本还原取。
契约正文见 `AGENTS.md` 的「creative_brief/2.0」一节；本文记审查依据与真实回放。

## 一、为什么改：审查发现

### 1. 简报大半字段在重复上游，或没有任何阶段在读

下发给候选阶段当「正向要求」的定位字段，是逐字抄原片分析：

| 简报字段 | 上游对应 | 5 个导出包里 |
|---|---|---|
| `targetAudience` | `referenceAnalysis.targetAudience.primary` | 4/5 逐字相同，另 1 个只多了半句 |
| `emotionStructure`（情绪 + 强度） | `referenceAnalysis.emotionCurve` | 5/5 相同 |
| `contentType` | `contentPositioning.format` | 基本照抄 |

按字段查消费者（主路径：full_story/1.1、direct_shot 3.0、自主分镜 4.0）：

| 字段 | 谁按字段读 |
|---|---|
| `recastTest` | 候选（只送 collapses）、候选评审——唯一既有校验又真有下游的 |
| 定位三项、`emotionStructure`、`nonNegotiableExperience` 前三项 | 候选（正向投影） |
| `storyEngine` | 只有候选评审；候选刻意不送（09-09 回放后撤回） |
| `protectedExpressions` / `controlledRewriteVariables` | 抽成「原片表面表达」词表；**角色边界阶段靠它过逐字绑定闸门**（见三 · R2） |
| `mustRetain` / `samePlotDriver` / `sameBeatValue` | 只进候选评审已降级的 `briefAlignment` |
| `allowedNarrativeComponents`、`roleAndOccupationMapping`、`minimumTransformationRules`、`creativeDistancePolicy` | 没有 |

原片分析与脚本还原都不提供、只有简报在做的，只有 `recastTest`（反事实判断）与 `turningMechanism` 的
before/after 写法。

### 2. 失败几乎全出在没人读的字段上

debug 里全部 82 次简报调用失败 16 次（qwen3.7-max 66/77；mimo-v2.6-pro 0/3；GLM-5.3 两次在 16384 截断）。
stage sidecar 的失败记录不写原因，7 次从任务库拿到错误消息，其余用各自 git 版本的校验器、配上它前 2–3 分钟
那次原片分析与脚本还原重跑还原（配对是推断，7 次里 6 次复现出具体错误，1 次未能复现）。

| 可归因的 13 次契约失败 | 次数 |
|---|---|
| 七项构件引文核对 `allowedNarrativeComponents` | **12** |
| `recastTest` 多写了一个 `recastNote` 键 | 1 |

七项构件那 12 次里：
- **4 次是原片确有其事、被误伤**：两次忠实转述覆盖率 0.74（线 0.75）；「从室内到街道再到回收站」0.64；
  「远景……乡村房屋外观」0.60（「乡村房屋外观」上游逐字就有）。
- 5 次引号里写的是构件的抽象定义而不是原片原文（「携带物品前往某地交接」0.14–0.20 三次，全在「送达任务」上）。
- 3 次格式：缺【原片有】前缀、缺引文、引号里填了字段名。

每次失败约 80–120 秒、1.5 万 token，整条 AI 导演链停住等人点重试。

### 3. 按字段名投影挡不住原片情节

`emotionStructure.function` 因为会写「获奖 → 转赠」被刻意剥掉，但 `stage` 照样写：6 个导出包里 3 个
（同一部参考片）的 stage 是「发展：爱心行动 → 高潮：获得奖励与反哺」这类，原样作为正向要求送进候选。
字段是不是抽象由名字决定，内容是不是抽象由模型决定。

### 4. 转述用户设定会造出第二份事实

09-23 那份简报写着「固定角色一律使用小白子与芙芙猫之名」，把搭档并进了「固定角色」，而简报会被整份送进
角色边界阶段——与 09-19 那次 5/5 失败同一个形状（只有这一个样本，是推断）。

## 二、改了什么

见 `AGENTS.md`「creative_brief/2.0」一节。要点：简报只收原片分析与脚本还原、只出两项；顶层多一个键就拒；
候选的定位、受众、情绪曲线与观看动力改由 `variantsSourcePositioningProjection` 从 `referenceAnalysis` 按内容
取舍（不取 `phase`、`trigger`、`contentPromise`、`whyWatchToEnd`、`payoff`）；角色边界不再读简报，改由服务端
从 `keyProps` 逐字摘出候选短词表；旧 3.0 分镜批次不再放整份简报；简报卡只显示这两项。

**角色边界签名摘要仍包含整份简报**，拿掉它会让所有已有 Run 的边界当场失效，需要带版本的摘要，本次不做。

### 结论与局限

- 简报本身：失败面从七项构件表缩到两个校验器，Qwen 6/6、MiMo 3/3，输出 token 少六成、耗时少一半以上。
- 角色边界：直接去掉简报会退化（Qwen 3/5），补上确定性 keyProps 候选词表后三个配置都达线或全过。
- 候选：逐字照抄与任务型欲望两项在三个配置下都没有变坏；成功批数在 MiMo 开思考下新组落后（1/3 对 3/3），
  两次失败的机制（字段名拼错、推理撑爆 32768 额度）都不直接指向简报内容，但样本太小，不能排除。
- 样本小：每个配置每组最多 3 批、12 个候选，都是 09-19 那三部参考片与同一份创作设定；
  Qwen 那半因为欠费没跑完。**这些数字只能说明「没看到变坏」，不能说明「变好了」。**
- 候选评审与展开前体检也读简报（提示词改了几句措辞），这次没有做真实回放。
