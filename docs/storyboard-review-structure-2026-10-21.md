# 4.0 分镜审阅：Claude 结构化输出与诊断（2026-10-21）

## 起因

4.0 分镜选 Claude Opus 5.5 时，「审阅分镜」这一步常常过不去。

回放用同一份冻结输入：《咕嘎和蜗牛》，加上生产路径上 Opus 写的分镜。脚本是 `scripts/storyboard-review-replay.mjs`，原始数据在 `reports/storyboard-review-replay-2026-10-21/`。

改动前（合并了生产那 2 次调用）：

- Opus 第一次调用就通过 2/6，两次预算内通过 4/6。
- 被拦的 6 次调用里，5 次是意见里的 `guidance` 写成了数组，1 次是引用漏了一个字。
- Sonnet 5.5 也有 1/6 次写成数组。MiMo 在别的故事上被拦过：一次漏了顶层 `guidance`，一次把引用键写成 `text`。

原因有三条：

- 输出协议里有两个同名的 `guidance`：顶层是字符串数组，意见里是一个字符串。
- 拦下时的诊断只写「reportedProblem / guidance 非空」，可数组明明非空，诊断从没说「必须是字符串」。有一次重试照样写成数组。
- 审阅重试用的是设计分镜的话术，叫模型「调整片段怎么分、各段多长」。

## 改了什么

判据不改：原来通过的照样通过，原来拦下的照样拦下。逐字核对不放宽。

**A. 诊断写清楚（所有模型）**

- `validateStoryboardReview` 一次报出全部问题，不再遇到第一处就停。
  - reason 写明哪个字段错成了什么样，例如「必须是一段非空字符串，写成了数组（2 项）」「引用只能有 id 与 quote 两个字段，写的是 id、text」「quote「…」不是 P015 正文里的逐字原文」。
  - 指针精确到出错的字段，例如 `/items/0/guidance`、`/items/0/originalEvidence/3`。
  - 三个 code 不变。
  - 测试里留了一份旧校验器的逐字副本，13 种输入逐个比对，两边通过与否一致。
- 新增 `storyboardReviewRetryPrompt`。与另外几份重试话术同一个形状：原提示词在前，末尾只追加诊断。收尾改成审阅用语：只修格式与引用，不因此删掉成立的问题。截断时另有一段话术。
- 键名常量只有一份（`STORYBOARD_REVIEW_KEYS` 等，在 `src/storyboard-review.js`），校验器与 Schema 共用。

**C. Claude 审阅带结构化输出（只给 Claude）**

- `src/contracts/storyboard-review-claude-schema.js`：只用 Claude 支持的子集，即 `type`、`properties`、`required`、`additionalProperties: false`、`items`。条数上限、非空、编号、逐字仍由校验器判。
- 请求参数叫 `claudeResponseSchema`。Claude 客户端收到它才发 `output_config.format`，与 effort 并存，不传时请求体逐字不变。
- 不叫 `responseSchema`，是因为 MiMo 认那个名字，用同一个名字会顺带改掉 MiMo 的审阅请求。另外三家按参数名解构，不认识的键直接忽略。
- 两道审阅（`storyboardReview`、`storyboardReviewFinal`）都带；协调器重试时沿用同一个 request。

## 验证

- `npm test` 1728 项全过。新增或改动的测试：
  - Claude 客户端带不带 Schema 的请求体；
  - Schema 只用允许的关键字、键名与校验器及提示词模板一致（用 Ajv 判符合与否）；
  - 逐阶段请求只有两道审阅带它；
  - 诊断的 code、指针与写法；
  - 审阅重试用的是审阅话术。
- 不花钱的核对：新代码判两份生产原文，报出的是 `/items/0/guidance`（数组）与 `/items/0/originalEvidence/3`（P015 漏字）。

## 一份审阅整份写成了英文 → 提示词加「所有文字用中文写」

带上 Schema 之后的第 3 个样本，strengths、guidance、意见正文全是英文，引用仍是逐字中文原文，所以过了校验。改动前 10 次调用没有出现过。审阅提示词此前从没写过用什么语言，Schema 的键名又是英文。

这件事有后果：审阅的 guidance 会进分镜的修订说明，页面上能看到（`public/storyboard-render.js`）；修订那一步也会读到英文的问题描述。

按用户决定，在审阅提示词的输出协议末尾加了一句「所有文字用中文写，quote 照原文逐字复制。」。

- 这句话所有模型都会看到，MiMo 也一样。
- 后半句是为了不和逐字引用打架：原文里本来就有英文时，quote 仍照抄。
- 测试锁住了这一句。

回放脚本另加了一列「英文为主的文字字段」：字母多于汉字的字段就算，quote 不算。用它数之前那份英文样本是 11/11，同批中文样本是 0/12。

同一份输入回放：

| | Opus 5 次（$1.15） | MiMo 3 次 |
|---|---|---|
| 第一次调用就通过 | 5/5 | 3/3 |
| 有英文为主字段的调用 | 0/5 | 0/3 |
| 引用逐字对上 | 17/17 | 14/14 |
| 报出至少一条问题 | 4/5 | 2/3（改动前 0/3） |
| 报出的问题与蜗牛有关 | 4/4 份都是：路线或速度 2 份，趴姿与鞋面朝向 2 份 | 2/2 份都是：蜗牛位置前后对不上，另一份还报了溶镜盖住上鞋过程 |
| 每次调用 | $0.21–0.25，42–60 秒 | 278–717 秒，输出 1.0 万–2.7 万 token（改动前 288–489 秒、1.1 万–1.8 万） |

MiMo 这次报出了问题，输出也变长了，分不清是这句话引起的还是抽样差异，因为每边只有 3 次。

## 不能保证的事

- 漏字（改动前 47 条里 1 条）仍靠重试兜底，结构化输出管不到内容。
- MiMo 审阅的结构失败不在本次范围：它的请求体逐字不变，只有诊断与重试话术变了。
- 审阅判得对不对，仍然没有确定性兜底。
- 只有一个故事、一份分镜，样本小。
