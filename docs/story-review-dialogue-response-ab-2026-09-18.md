# 评审补「台词在回应什么」这一问：两轮真实回放（2026-09-18）

脚本、事前登记与全部原始输出在 `~/Downloads/story-review-dialogue-ab-2026-09-18/`
（`预先登记.md`、`run.mjs`、`analyze.mjs`、`out/`）。这里是摘要，下载目录被清掉也能看懂结论。

## 起因

《蒲扇下的毛豆游戏》V4 第 5 拍：「小白子端着煮好的毛豆走到奶奶身边，剥了一个最大的喂进奶奶嘴里，
清晰地说了一句「谢谢」」——**付出的一方自己道谢**。ChatGPT 的点评把它列为这篇的主要问题
（「这句谢谢具体回应什么，没有紧贴眼前动作……需要观众自行补足」）；我们的三道评审全部漏掉，而且都当成了优点：

| 阶段 | 次数 | 原文 |
|---|---|---|
| 候选对照评审（整批） | 3 次 + 1 次重试 | 对白维度 9–9.5：「小白子简单的「谢谢」，极度贴合生活化语境」 |
| 展开前体检的候选评审 | 1 次 | 对白 9.0：「小白子只说谢谢**符合简单人话设定**」；`keepThis` 要求保留「说谢谢的自然情感兑现」 |
| 剧情体检·编辑诊断 | 1 次 | 没提这句 |
| 剧情体检·承诺核对 | 1 次 | 把「清晰地说了一句「谢谢」」当成候选承诺，判 PRESERVED |

**根因三层**：

1. **源头在候选生成**：用户设定「小白子会“谢谢、再见”等简单人话」，候选模型把这两个词当展示项塞进结尾
   （V4 的 dramaticFunction：「通过反哺动作与**简单人话**完成情绪兑现」）。同一批 V1 也是分享果酱后自己说谢谢。
   回扫 275 个历史候选，「刚付出就道谢 / 谢谁看不出」十几例，另一批用括号自我辩解「说'谢谢'（谢奶奶平时照顾）」。
2. **评审问错了问题**：候选评审第 11 维只问「对白像不像这个角色会说的话」，creatorProfile 作为硬事实送进来，
   合规被读成加分；剧情体检九类问题里没有台词这一类，剧情自己的角色表还把「双手捧脸颊表达感谢」登记成了招牌动作。
3. **生成侧有、评审侧没有**：`fullStoryPrompt` 早就逐句问「这个角色此刻为什么对这个对象说这句话」「凭什么已经知道」，
   三道评审没有一条对应。

## 样本（全部真实数据）

- 正例·剧情级：毛豆 S5（设计样本）；午后的阶梯餐厅 S3（喂完小动物后「谢谢。」）；黄昏电车的录音笔 S4、
  晨雾中的智能音箱 S4（递东西后自己说谢谢，理由只写在 deliveryOrSubtext 里）；被遗忘的信箱 S3（村民道谢后她回「谢谢！」）。
- 正例·候选级：毛豆 V4；被遗忘的信箱 V3；够不到的风铃 V3；黄昏电车的录音笔 V3（理由只写在括号里）。
- 边界（不计分）：溪畔的约定画像（递画前一拍对方刚当过模特）。
- 反例：风铃与香囊、雨中的企划书、追风的小猫娘、屋檐下的红豆汤、光影八音盒、糖浆泡泡糖葫芦；
  同篇对照：录音笔 S6、智能音箱 S6（被邀请后道谢，方向正确）。
- 模型：qwen3.7-max，与生产同一个 QwenClient 配置；被拦下按生产同一份重试提示词重做一次，禁止第三次。

## 第一轮：只问方向

剧情体检新正例 7 次有效里抓到 6 次，反例 0 误报；**毛豆 0/2**（一次 0 条问题，总结「角色语言与行为严格符合设定」）。
候选评审：信箱 2/2、风铃 1/1 有效、录音笔 1/2；**毛豆有效的一次漏了**，理由是「小白子的「谢谢」回应了奶奶煮豆子的
**隐性付出**」（候选里根本没写奶奶煮豆子）。失败形状只有一个：**替方向相反的道谢找理由**。

## 第二轮：「观众能不能不靠猜，就说出他在谢什么」

这是事前登记允许的唯一一次措辞修正，判据换成 ChatGPT 对这句的实际判据。它同时让「递画谢刚当过模特的对方」这类合法写法保持成立。

| | 旧提示词 | 第一版 | **第二版（已落地）** |
|---|---|---|---|
| 剧情体检·毛豆 | 0/1 | 0/2 | **2/2**（MAJOR），落地后开发服务器上再跑 1/1 |
| 剧情体检·四份新正例 | 2/4，都只判 MINOR | 6/7 | **8/8** |
| 剧情体检·反例里方向正确的道谢 | — | 0 / 6 次有效 | **0 / 12 次** |
| 候选评审·毛豆进因果断裂 | 0/4（生产侧车里的有效评审） | 0/1 有效 | **1/2** |
| 候选评审·信箱 / 风铃 / 录音笔 | 1/1、0/1、0/1 | 2/2、1/1、1/2 | 2/2、2/2、**0/2** |
| 候选评审·反例误报 | — | 0 / 4 次有效 | 0 / 2 次有效 |

通过线判定：剧情体检两条全过；**候选评审「毛豆 2/2」没过**（另一次看出来了——「观众需猜测是谢烹饪还是谢陪伴」——
却只扣分没升级成断裂）。**用户看过数据后明确选择两处都落地**：展开前体检漏掉的由剧情体检兜住，误报的代价低
（修订稿要用户点采纳才生效）。

另两条需要人看的：反例《红豆汤》多报了一条「画面是竹匾、台词说篮子」，确有其事但判成 MAJOR 偏重；
边界样本《溪畔》第二版被判成接不上——**第二版比第一版严**。

## 端到端（生产原样）

- **root 修订**：把第二版判出的断裂交给 `/api/story-candidate-revision`（`scope: root`），第 5 拍「谢谢」→「奶奶吃」，
  其余拍一字未动，签发复验通过。
- **按问题修改**：落地后剧情体检报出 S5，交给 `/api/story-quality-repair`：在喂完之后补半句
  「奶奶笑着也剥了一颗喂进小白子嘴里，小白子开心地嚼着」，再捧脸说谢谢——**两条候选承诺（喂奶奶、说谢谢）都保住了**，
  谢谢有了看得见的对象，`status: applied`。

## 代价与局限

- 两轮 + 端到端约 ¥25。85 份记录里 18 份整次作废：传输中断（`terminated` / `fetch failed`）与候选评审现有 schema 的老毛病
  （`dimensions/6/evidenceRefs` 超 2 条最常见），与本次改动无关，失败原样留档。候选评审反例因此只有 2 次有效（第二轮）。
- **判得对不对、判多重都没有确定性兜底**；5 份正例里毛豆是设计样本，过线只说明「在这批样本上不再漏」。
- 候选评审放过**理由写在括号里**的道谢（录音笔第二轮 0/2）——评审读得到括号，观众读不到。
- 冻结的 `visualPotential` 在 root 修订后仍写着「说「谢谢」」，而它同时进展开输入与承诺核对（`docs/待解决项.md` 第 14 条）。
