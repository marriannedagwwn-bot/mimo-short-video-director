## 1. 项目定位与当前交付边界

“母题导演台”是一个本地运行的 AI 动画短视频受控改编工具。它接收参考视频和可选字幕，提取可复用的叙事价值，绕开原片具体表面表达，再围绕用户固定角色生成新故事、结构化首尾帧动画生产包及媒体候选。

当前仓库负责：

- 参考视频读取、浏览器抽帧和可选原生视频理解；
- `referenceAnalysis → sourceScriptReconstruction → creativeBrief → visualGuardrails → themeVariants`；
- 选择主题后生成 `fullStory`；
- 服务端拆分生成并合并 `animationPlan v2`；
- 角色参考图和逐镜首帧／尾帧候选图；
- 选定当前 shot 的首尾帧后，通过可灵 AI 生成 1–4 个单镜头候选视频；
- 导出 JSON 生产包或复制 Markdown 给外部供应商程序。

当前仓库不再负责：

- JSONL 视频任务队列；
- `plan:video`、`exec:video`、`preflight:video`、`make:video`、`report:video`；
- production workspace、批量 command worker、本地质检、失败队列和 ffmpeg 成片合成。

必须继续保留的“视频”概念包括：输入参考视频理解、`motion`、`videoPrompt`、`negativePrompts.video`、首尾帧图片、单镜头可灵试片、JSON/Markdown 供应商交付，以及只负责分析输入视频的 `npm run run:video`。

## 4. 端到端工作流

1. 用户上传参考视频；浏览器读取元数据，均匀抽取 6–10 帧，最长边 720px、JPEG 质量约 0.72。
2. 文件大小和 provider 配置允许时，页面同时准备原生视频 Data URL；否则只发送关键帧。
3. 点击“启动 AI 导演”后，前端串行调用：
   `analyze → reconstruct → brief → visual-guardrails → variants`。
4. 用户选择一个主题变体，单独调用 `/api/full-story`。
5. 完整剧情页调用 `/api/animation-plan`。前端只看到一次请求；服务端内部拆成基础锁定、若干 shot 批次和最终合并。
6. 用户可生成／选择角色参考图。
7. 用户按 shot 生成并选择首帧、尾帧候选图。
8. 当前 shot 具备已选首尾帧后，可点击“生成此镜头视频”，由可灵生成候选。
9. 用户导出 JSON 或复制 Markdown 给外部供应商继续批量制作。

重要限制：前端 `runWorkflow()` 开始时会清空所有已有输出。任一导演阶段失败后，页面没有“从失败阶段继续”，再次点击会重跑已经成功的前置阶段。

## 5. 已完成但尚未全部提交的核心改造

### 5.1 逐镜负面提示词

- `visualGuardrails` 不再生成全局 `commonNegativePrompt`。
- 角色正向边界、原片相似性、台词规则和实际渲染负面词已拆开。
- 每个 shot 分别拥有 `negativePrompts.image` 与 `negativePrompts.video`，两个数组均允许 `[]`。
- 条目要求 `text`、`appliesTo`、`triggerEvidence`、`reasonCode`、`priority`，可选 `enabled`。
- 不允许 `unspecified_feature`；“用户未声明”不能成为唯一理由。
- 图片和视频只编译当前 shot、当前媒介、`enabled !== false` 的词。
- 可灵 preset 将当前 shot 的视频负面词真实写入 `negative_prompt`；即梦不伪造不支持的独立 negative 字段。

### 5.2 `animationPlan v2`

新计划使用 `promptSchemaVersion: "2.0"`。每个 shot 的单一事实源为：

- `startFrame`：完整静态起点；
- `endFrame`：完整静态终点；
- `motion`：唯一主要动作、摄影机路径、情绪变化、1–4 个连续 timing beats、音频意图、保持项和停止条件。

服务端编译器派生并保持兼容：

```text
startFramePrompt
endFramePrompt
videoPrompt
cameraMotion
characterAction
dialogueOrSubtitle
soundDesign
continuityNotes
```

模型不得独立写第二套字符串；v2 结构与已有兼容字符串不一致时必须失败并进入当前批纠偏。无版本的旧 animationPlan 继续按 legacy 读取，不从自然语言反推结构。

### 5.3 animationPlan 拆批

`POST /api/animation-plan` 的公开契约不变，服务端内部：

1. 生成 `animationFoundation`：`visualBible`、角色／场景／资产参考及全局字段；不生成 shot。
2. 默认每两个 `fullStory.sceneScript` 场次生成一批 `{ shotPlan }`。
3. 每批独立校验和纠偏，并继承上一镜完整尾帧状态。
4. 服务端按剧情顺序合并，统一编号 `A01...`，重写负面词证据路径，编译兼容字符串并做最终校验。

前端、导出和媒体生成继续读取合并后的旧兼容字段，因此无需全面重写页面。

### 5.4 15 分钟模型超时

以下默认值均已调整为 `900000ms`，且支持环境变量覆盖：

- `MIMO_REQUEST_TIMEOUT_MS`
- `QWEN_REQUEST_TIMEOUT_MS`
- `SERVER_REQUEST_TIMEOUT_MS`

注意：`SERVER_REQUEST_TIMEOUT_MS` 主要约束接收请求体，不替代 MiMo/Qwen 客户端生成超时。此次 AI 导演问题返回 502，不是 504，禁止再用提高 timeout 解决。

### 6.3 确定性根因

调用链：

1. `public/app.js:411-481` 串行运行导演阶段。
2. `server.js:29-42` 将 `/api/brief` 路由到 `workflow.createBrief()`。
3. `src/workflow.js:105-115` 先检查 creativeBrief 结构，再调用 `ensureCreativeBriefMatchesProfile()`。
4. `src/prompts.js:227-229` 同时要求解释原片动物外壳不能继承，却没有明确区分“用户授权猫娘”和“原片动物外壳”。
5. `src/validation.js:1396-1399` 把泛词 `动物`、`动物形象` 放进硬身份禁词。
6. `incompatibleProtagonistSurfaceTerms()`（约 `1721-1726`）只做字面豁免：fixedCharacter 必须逐字包含“动物”。`猫娘`／`猫耳少女`不会获得语义豁免。
7. `ensureCreativeBriefMatchesProfile()`（约 `825-850`）把 `newRole`、`newOccupationOrIdentity`、`mappingLogic` 合并成 JSON 字符串。
8. `assertNoTerms()`（约 `1765-1772`）只做 `includes()`，不识别字段，也不识别否定语境。

因此下列完全正确的解释也会失败：

```json
{
  "newRole": "小白子作为主角",
  "newOccupationOrIdentity": "村里的热心帮手",
  "mappingLogic": "不继承原片拟人化动物身份，只保留任务执行功能"
}
```

该最小夹具已在本地直接调用 validator 复现出同一个“动物”错误。根因不依赖本次未保存的 raw 模型输出。

### 6.4 为什么一次纠偏没有解决

`src/workflow.js:181-199` 只在第一次 `OutputContractError` 后生成一次纠偏结果；第二次 `validate(second)` 失败后直接冒泡。`validationRetryPrompt()` 会重复原始 Prompt，仍然包含“动物不得继承”，但错误信息没有字段路径，也没有说明猫娘是用户授权身份。

MiMo/Qwen 客户端自身的 JSON retry 只解决无效 JSON／截断 JSON。本次两份输出可以是合法 JSON，只是业务校验冲突，因此客户端 retry 不会参与。

### 6.5 最小且安全的修复方案

优先只修改 `src/validation.js`、`src/prompts.js` 和对应测试；不要碰 animationPlan v2。

1. **改为字段级校验**：
   - `newRole`、`newOccupationOrIdentity` 作为目标身份字段继续严格拦截来源泄漏；
   - `mappingLogic` 使用项目已有的否定语境识别逻辑，例如 `findFieldTermHits(..., { allowNegativeContext: true })`，或者不把否定来源说明当作目标身份扫描；
   - 错误中必须返回 `roleAndOccupationMapping[i].字段名`。
2. **泛词条件式授权，不要全局放开**：
   - `企鹅`、`企鹅服`、`玩偶服`、`兽装`、`头套`等具体来源身份继续硬拦截；
   - `动物`／`动物形象` 只有在同一目标字段同时出现 fixedCharacter 明确授权的身份词（例如本例的 `猫娘`／`猫耳少女`）时才允许；
   - 普通人类角色的“动物快递员”仍必须失败；
   - 只有猫耳配饰不能自动授权任意动物身份，更不能授权爪子、肉垫、翅膀或其他尾巴。
3. **同步修改 brief Prompt**：
   - 明确用户 fixedCharacter 中的猫娘身份不是原片表面表达；
   - 目标身份优先复述用户原词，禁止概括成新物种；
   - 来源外壳对比放在 `sourceFunction`／`protectedExpressions`，`mappingLogic` 只解释剧作功能。
4. **不要先增加重试次数**。可以补 brief 专用纠偏提示，但它只能作为辅助，不能代替 validator 修复。

### 6.6 必须新增的回归测试

- 保持现有企鹅泄漏测试继续通过。

## 7. 第二个独立问题：sourceScriptReconstruction 无证据改写

本次 reconstruction 虽通过结构契约，但页面输出把字幕中明确的：

- “咕嘎”改名为“小栗”；
- “李奶奶”改为“王奶奶”；
- 新增社区活动室／储物间；
- 新增手写便签和旧自行车；
- 新增小栗自己的录音；
- 把原本“奶奶留咕嘎吃饺子”的结尾改成红薯干。

而且部分无证据内容被标为 85–95% 置信度。

`src/prompts.js:192-216` 已写“按证据最大限度复原”，但 `src/workflow.js:90-102` 只执行通用 `ensureOutputContract()`；当前校验只能证明字段齐全，不能证明内容忠于字幕和画面。

建议按独立问题处理，避免与“动物”误杀混成一个大改动：

1. Prompt 明确证据优先级：用户 transcript 中的姓名、对白对象、关键道具和结尾动作高于模型补全。
2. 禁止给明确人物改名；未知姓名使用“主角／老人”等原标签，不创造新名字。
3. 采样间隙的推测只能进入 `uncertainties.safeAssumption`，不能同时晋升为 scene 的确定事实。
4. 每个 scene 的 `sourceEvidence` 必须指向时间码、画面编号或 transcript 时间段。
5. 无直接证据的地点、道具、对白和结尾不得给高置信度。
6. 可新增 `ensureReconstructionGrounded()`，至少校验显式 transcript anchors、证据格式和置信度；不要依赖另一轮自由创作模型来“审查”而没有确定性回归。

最低回归夹具应使用本次关键 transcript：输入明确“咕嘎／李奶奶／录音／饺子”，输出不得改为“小栗／王奶奶／自录问候／红薯干”。

## 8. 第三个问题：导演阶段失败后无法续跑

`public/app.js:411-428` 每次点击会清空：

```text
state.output
state.fullStories
state.animationPlans
state.shotVideoResults
state.shotFrameResults
state.characterReferenceStatuses
selectedVariantId
```

因此 brief 失败后，用户无法复用已经成功、且耗时约 3 分钟的 analysis/reconstruction。

建议的最小改造：

- 为一次导演输入计算 signature：视频元数据／帧摘要、transcript、creatorProfile、模型 overrides；
- signature 未变时保留已成功阶段，只从第一个缺失或失败阶段继续；
- signature 变化时明确提示并重新开始；
- 页面提供“重试此阶段”或“从失败阶段继续”；
- 不要把旧结果和新输入静默混合；
- 如需持久化，优先导出／导入阶段 JSON，不要突然引入数据库。

该问题属于体验和费用优化，不是本次 502 的根因。优先修 validator，再实现续跑。
