## 要回答的问题

体检报出的每条问题，能不能附上一个**程序可以逐字执行**的局部修改，用户点「采纳」后服务端精确替换、
重跑完整签发校验、签发新的 fullStory 版本？——参考命题定向修订那套「修订 → 预览 → 采纳」。

## 修改的形状与执行规则（两轮相同）

每处修改 `{sceneId, field, find, replace}`，`field` ∈ visibleAction / shotAndSound / dialogue，一条问题
≤ 3 处。服务端执行：`find` 必须在该场该字段**逐字出现恰好一次**；台词里整句原文 + 空替换 = 删这一句；
执行后跑与 `createFullStory` 同一条签发校验链。「修好没修好」的判定：把一次试验里全部合法修改一起打上，
**用生产原版体检提示词再体检一次**，看同一问题还在不在。

## 第六轮：体检时顺手写修改

生产的两段体检提示词逐字不变，只在输出格式前插一段修改规则、模板里多一个 `patches` 字段。

| # | 指标 | 结果 | 通过线 |
|---|---|---|---|
| P1 | 附了修改的比例 | 30/30（重条目 12/12） | ≥ 60% ✔ |
| P2 | `find` 逐字命中恰好一次 | 30/30 | ≥ 90% ✔ |
| P3 | 改完通过签发校验链 | 30/30 | ≥ 90% ✔ |
| P4 | 复检里同一问题不再出现 | 全修好 26/32（81%），半修好算 0.5 为 91% | ≥ 70% ✔ |
| P5 | 复检新出现的 MAJOR/BLOCKER | 4 条 | ≤ 1 ✘ |
| P6 | 执行者反转 / A或B / 加角色奖励 / 点题台词 | 0 | ≤ 10% ✔ |
| P7 | 诊断不漂移 | 「无声」2/2；台阶无前置 1/2；风铃修好版无 MAJOR 2/2 | 各 2/2，部分 ✘ |

P5 的 4 条全部落在**修改没碰过的文字**上，是复检自己的抖动——这条线登记得不好，按字面仍算不通过。
P7 的台阶那条，同一份剧情用生产原版提示词跑的基线也没报。

**登记时没想到、复检读出来的真问题**——修改直接引起的退化：

| 样本 | 修改 | 复检报了什么 |
|---|---|---|
| 蚂蚁搬家 | 「双手扶稳」→「双手松开保持平衡」 | 候选写的是「双手扶着」→ **CONTRADICTED** |
| 追风 | 「放下竹篓」→「盖紧竹篓」 | 候选写了「放下竹篓」→ WEAKENED |
| 糖葫芦 | 「冷却结皮」→「温度逐渐降下」 | 候选关键选择原文就是「冷却结皮」→ WEAKENED |
| 阶梯餐厅 | 为减动作删掉「分成均匀小份」「和石头」 | → WEAKENED |
| 阶梯餐厅 | 删光路人少女的动作、脚步声和台词 | 她还登记在 `characters` 里，复检报「角色表有、画面里没有」 |

**根因只有一个：编辑诊断刻意看不到候选**（五轮实测定下来的，它诊断准正是因为没被候选带着走），
同一个盲区让它写修改时不知道哪些动作是候选承诺过的。与 2026-09-17 编辑点评测试的结论同类
（「最大的风险在改法，不在发现问题」），区别是那次的改法没真正执行过，这次执行、签发、复检，量出了代价。

## 第七轮：体检不动，另起一次看得见候选的修改调用

输入 = 完整剧情 + 候选投影 + 选中的问题 + **体检判为守住的承诺清单（不得改坏）**。每条可以不改，
但必须在 note 里说明。执行器加一道确定性闸门：修改不得让一个出镜角色从本场的动作和对白里消失。
问题清单用第六轮 10 次体检报出的**同一批**（去掉它们顺手写的修改），两轮逐条可比。

| # | 指标 | 第七轮 | 通过线 | 第六轮 |
|---|---|---|---|---|
| Q1 | 可执行且改完合法 | 26/26 | ≥ 90% ✔ | 30/30 |
| Q2 | 复检里同一问题不再出现 | 全修好 85%，半修好算 0.5 为 92% | ≥ 70% ✔ | 81% / 91% |
| Q3 | 修改直接引起的承诺退化 | **1** | ≤ 1 ✔ | **4** |
| Q4 | 修改直接引起的其它新问题 | 1 | ≤ 4 ✔ | 约 4 |
| Q5 | 出镜角色被删成幽灵 | 0 | 0 ✔ | 1 |
| Q6 | 选择不改的比例 | 6/32（19%） | ≤ 40% ✔ | 0% |

第六轮改坏的几处：「双手扶着」两次都保住（「双手扶稳，随后松开手保持平衡」）；「放下竹篓」两次都保住
（「放下竹篓并扣紧盖子」）；糖葫芦一次**保留「结皮」、改起泡的原因**（「扇风让糖浆内部热气顶起冷却的糖皮」），
一次选择不改并说明冲突——登记时说两种都算对。

**唯一那次退化是明知故犯**：阶梯餐厅那条承诺就在交给它的清单里，它为了解决「8 秒动作太挤」（MAJOR）
删了「均匀」「石头」，note 里如实写了「去掉了石头和均匀等细节」，但没把它标成冲突。所以
「不得改坏承诺」**不是确定性保证**，页面必须把 note 与逐字对照摆在采纳按钮前面。

**选择不改的 6 条**：4 条是毛病出在候选本身（候选高潮原文就是「戳破并卷起」、关键选择原文就是
「冷却结皮」、emotionalPayoff 写的就是「完好的干花」、候选写的就是「长椅另一端」），1 条认为问题不成立
（「接下」也可指拿下），1 条同上的「戳破」。**同一条问题两次决定会抖**：「完好的干花」一次拒改一次改，
「长椅另一端」一次改一次拒。

## 首次生产路径真实调用（落地当天，浏览器端到端）

《糖浆泡泡糖葫芦》原包导入 → 体检（两次调用约 95 秒）→ 5 条全选 → 修改一次调用 36 秒、3419 completion
tokens。结果：「冷却结皮」「戳破」「动作密度」3 条因与候选冲突拒改；「路人小孩没铺垫」那条把本场没登记的
「路人小孩」写进了 S3 的可见动作，**被签发校验链拦下、只拒这一条**；「透明」承诺改成（S5 台词
「哇，好脆！」→「哇！是透明的糖葫芦！好脆！」）并采纳，服务端签发 `fullStory-V2-r2`、r1 被取代。

## 已知缺口

1. 5 份样本里 4 份是开发回归集，追风是唯一盲样本。**全过也只是偏乐观的上界。**
2. 「修好没修好」靠复检判断，复检本身会抖（第六轮 P5）。
3. 「不改」由模型决定：它可能拒绝一条能修的问题，也可能像阶梯餐厅那样该拒绝时没拒绝。
4. 毛病出在候选本身时只能拒改，本版不提供「接受偏离候选、强制改」的出口。
