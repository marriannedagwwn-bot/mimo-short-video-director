# 母题导演台项目交接文档

## 1. 项目定位

本项目是一个本地运行的 AI 短视频受控改编工具。它从参考视频中提取可复用的叙事结构，绕过原片的具体表面表达，再围绕创作者指定的固定角色和垂直赛道生成新的完整剧情与逐镜动画生产包。

仓库的输出边界现在是：

- 生成并校验 `animationPlan`；
- 生成角色参考图和镜头首尾帧图片；
- 使用已选首尾帧调用可灵 AI 生成单镜头候选视频；
- 导出 JSON 或复制 Markdown 生产包给外部供应商程序。

仓库只保留页面内的单镜头可灵试片链路。JSONL 任务队列、production workspace、批量执行、本地质检和成片合成已移除；整片生成与后期仍由供应商提供的程序负责。

## 2. 用户主流程

1. 用户上传参考视频，浏览器读取元数据并抽取 6–10 张带时间戳关键帧。
2. 后端依次生成 `referenceAnalysis`、`sourceScriptReconstruction`、`creativeBrief`、`visualGuardrails` 和 `themeVariants`。
3. 用户选择一个主题变体，生成 `fullStory`。
4. 服务端先生成 `visualBible` 与角色／场景／资产参考，再每 2 个剧情场次分批生成结构化 `shotPlan`，最后合并、重编号、编译兼容 Prompt 并校验成公开 `animationPlan`。某批失败时只纠偏当前批次。
5. 用户可以在页面生成角色参考图和逐镜首尾帧图片，选定两张图后调用可灵生成 1–4 个当前镜头候选视频。
6. 用户导出当前生产包 JSON，或使用“复制动画生产包 Markdown”，交给外部供应商程序进行整片批量生成。

## 3. `animationPlan` 交付契约

前端和外部程序只读取服务端合并后的完整结构。分批阶段的私有 `sourceSceneIds` 不得出现在 API 响应或导出文件中。

新生成计划使用 `promptSchemaVersion: "2.0"`。每个 `shotPlan[]` 的事实源是：

- `startFrame` 与 `endFrame`：两份完整静态端点，包含角色姿态/手持物/视线/表情、前中后景、摄影机和光线；
- `motion`：一个主要动作、摄影机路径、情绪变化、1–4 个连续时间段、声音意图、保持项、尾帧停止条件和可选后期变速建议；
- `negativePrompts.image` 和 `negativePrompts.video`，两个数组都允许为空；
- 逐镜验收标准。

为兼容现有页面、即梦首尾帧和可灵单镜头调用，每个 `shotPlan[]` 仍保留服务端编译出的：

- `startFramePrompt` 和 `endFramePrompt`；
- `videoPrompt`、镜头运动、角色动作、对白/字幕、声音设计和连续性备注。

禁止模型独立输出这组兼容字符串。结构与兼容字段并存但内容不一致时必须进入当前纠偏重试，不能用 `a || b` 静默选值。无 `promptSchemaVersion` 的旧计划按 legacy 读取，不从自然语言猜测结构；JSON 生产包版本为 `2.1`，旧 `2.0` 包继续可导入。

逐镜负面词条目必须包含 `text`、`appliesTo`、`triggerEvidence`、`reasonCode` 和 `priority`，可选 `enabled`。“用户未声明”不能成为负面词的唯一理由。外部供应商程序应只编译当前 shot、目标媒介匹配且 `enabled !== false` 的条目。

内置单镜头可灵路径会把当前 shot 已启用的 `negativePrompts.video` 编译到可灵 `negative_prompt`，并在回执中记录 `negativePromptDelivery` 与脱敏 `requestPreview`。外部批量程序仍必须自行验证它的支持能力、字段映射和最终请求快照。

## 4. 核心模块

| 路径 | 职责 |
| --- | --- |
| `server.js` | HTTP 路由、静态文件、健康检查、图片／单镜头视频持久化和错误映射 |
| `public/app.js` | 页面状态、视频抽帧、阶段调用、动画包展示、首尾帧图片、可灵单镜头候选和供应商交付 |
| `src/workflow.js` | 阶段 provider/model 路由、动画基础／镜头分批生成、合并与纠偏 |
| `src/animation-prompt-compiler.js` | 将 v2 首帧、尾帧和 motion 确定性编译为兼容 Prompt，并检测双写冲突 |
| `src/prompts.js` | 各 LLM 阶段提示词与 animation foundation/shot batch 契约 |
| `src/validation.js` | 输入与输出契约、角色边界、原片规避、负面词证据和相关性裁剪 |
| `src/jimeng-client.js` | 即梦／Seedream 角色参考图与镜头首尾帧图片生成 |
| `src/shot-video-generator.js` | 将当前 shot 的已选首尾帧、提示词与负面词交给可灵，管理 1–4 个候选视频 |
| `workers/generic-http-worker.mjs` | 可灵 preset、异步轮询、mp4 下载、negative prompt 传递和脱敏回执 |
| `src/mimo-client.js` / `src/qwen-client.js` | 模型请求、媒体输入、JSON 解析与回退 |
| `src/run-video-command.js` / `src/video-file.js` | 本地参考视频分析 CLI 与 ffmpeg 抽帧；不是输出视频生成 |
| `test/animation-plan-batching.test.js` | 分批生成、独立纠偏、合并与证据路径回归测试 |
| `test/negative-prompts.test.js` | 逐镜负面词分类、证据、空数组和图片编译回归测试 |

## 5. API 清单

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 运行模式、阶段模型和可用性 |
| `POST /api/analyze` | 参考片分析 |
| `POST /api/reconstruct` | 原片脚本还原 |
| `POST /api/brief` | 创意简报 |
| `POST /api/visual-guardrails` | 角色正向边界、原片规避和台词规则 |
| `POST /api/variants` | 主题变体 |
| `POST /api/full-story` | 完整剧情 |
| `POST /api/animation-plan` | 合并后的首尾帧动画生产包 |
| `POST /api/refine-character-reference` | 使用上传图片修正角色参考描述 |
| `POST /api/generate-character-reference-images` | SSE 流式生成角色参考图 |
| `POST /api/generate-shot-frame-image` | 生成单镜头首帧或尾帧候选图 |
| `POST /api/generate-shot-video` | 用已选首尾帧调用可灵生成单镜头候选视频 |
| `POST /api/run` | 一次执行到主题变体阶段 |

通用 POST 响应为 `{ ok, mode, result }`。

## 6. 配置与运行

- 运行时固定为 Node.js 24 LTS：进入仓库后先使用 `.nvmrc` 切换版本；`package.json` 的支持范围是 `>=24 <25`。
- `MIMO_*` 和 `QWEN_*` 配置 LLM 与参考视频理解。其中 `*_VIDEO_*` 表示输入视频模型或抽帧参数，不是输出视频生成；`MIMO_REQUEST_TIMEOUT_MS`、`QWEN_REQUEST_TIMEOUT_MS` 默认均为 `900000`（15 分钟）。
- `SERVER_REQUEST_TIMEOUT_MS` 默认 `900000`，只约束服务端接收完整请求体，不应误当成模型生成总时长上限。
- `JIMENG_*` 配置角色参考图和镜头首尾帧图片生成。
- `VIDEO_HTTP_VIDEO_ENDPOINT`、`VIDEO_HTTP_VIDEO_MODEL`、`VIDEO_HTTP_PRESET=kling_image_to_video`、`VIDEO_HTTP_API_KEY` 和轮询参数配置单镜头可灵生成。
- `.env` 包含私密配置，不得复制到文档、日志、测试夹具或 Git。

启动与验证：

```bash
npm start
npm test
curl http://localhost:4173/api/health
```

`npm run run:video -- <reference.mp4> ...` 仍保留，它使用 ffmpeg/ffprobe 抽取本地参考片，再导出创意 JSON。该命令不生成成片。

## 7. 已移除能力

以下批量生产流水线内容不应在页面、配置、脚本、文档或测试中再出现：

- 视频任务队列 JSONL 导出与页面队列预览；
- `plan:video`、`exec:video`、`preflight:video`、`make:video` 和 `report:video`；
- command worker 协议、local postprocess worker；
- production workspace、mock 产物链、质检、失败回执和本地成片合成。

不要误删输入参考视频理解、`animationPlan.videoPrompt`、`negativePrompts.video`、首尾帧提示词或 JSON/Markdown 供应商交付。
