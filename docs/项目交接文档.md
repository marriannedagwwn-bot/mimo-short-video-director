# 母题导演台项目交接文档

> 交接基线：2026-07-20；分支 `master`；本工作区已完成逐镜负面提示词证据化重构，最终测试数以本文“当前状态”为准。

## 1. 项目概述

“母题导演台”是一个无第三方 Node.js 依赖的 AI 短视频受控改编 MVP。它接收参考视频，先分析原片的定位、受众、情绪内核、剧情驱动力和高价值桥段，再围绕创作者指定的固定角色与垂直赛道生成新主题、完整剧情和逐镜动画生产包，最后可将动画计划转换为可执行的图片、首尾帧视频、质检和剪辑任务。

产品原则是同时满足：

- 体验保真：保留定位、受众、核心情绪、剧情驱动力和高价值桥段。
- 表达原创：重新设计人物、任务、道具、对白、场面调度和镜头表达。

当前代码已经覆盖“创意生成 + 生产任务编排 + 通用供应商 worker + 本地后处理”的基础闭环；尚未达到完整产品化状态，重点缺口是前端生产控制台、真实供应商端到端验收、连续性控制和自动化质检。

## 3. 用户主流程

1. 用户上传参考视频，浏览器读取元数据并抽取 6–10 张带时间戳关键帧。
2. 后端依次生成：
   - `referenceAnalysis`：参考片分析；
   - `sourceScriptReconstruction`：原片脚本还原；
   - `creativeBrief`：可复用结构、受控改写变量和禁止复制表达；
   - `visualGuardrails`：固定角色身份/正向边界、原片表达规避和台词规则；该阶段不生成渲染负面词；
   - `themeVariants`：三个可拍摄主题变体。
3. 用户选择一个主题变体，生成 `fullStory`。
4. 基于完整剧情生成 `animationPlan`，包含视觉圣经、角色参考、资产提示词、逐镜首帧/尾帧/video prompt、分开的 `negativePrompts.image` / `negativePrompts.video` 和验收标准。每条渲染负面词都携带证据、原因码、优先级与媒介范围，数组允许为空。
5. 用户可在页面内：
   - 用即梦生成角色参考图及镜头首尾帧；
   - 用通用 Video HTTP 配置生成单镜头视频候选；
   - 导出完整生产包 JSON；
   - 导出视频任务队列 JSONL；
   - 复制 Markdown 格式的视频模型生产包。
6. JSONL 队列可进入本地生产流水线：生成 workspace → 预检 → 调用真实 worker → 本地质检 → ffmpeg 合成 → 查看报告。

注意：页面的前五个创意阶段可以在未配置模型时使用演示数据运行；图片、真实视频和真实模型判断不能由演示模式替代。

## 4. 技术架构

### 4.1 运行形态

- 单进程 Node.js HTTP 服务，入口为 `server.js`，默认监听 `4173`。
- 静态前端位于 `public/`，没有构建步骤和前端框架。
- API 使用 JSON；角色参考图生成使用 SSE 流式返回。
- 前端使用浏览器原生 API 完成视频抽帧、状态管理、文件导出和本地配置保存。
- 模型 API 均从服务端调用，密钥只保存在 `.env`/进程环境中。

## 5. API 清单

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 返回运行模式、各阶段模型、provider 配置与模型可用性 |
| `POST /api/analyze` | 参考片分析 |
| `POST /api/reconstruct` | 原片脚本还原 |
| `POST /api/brief` | 创意简报 |
| `POST /api/visual-guardrails` | 固定角色正向边界、原片表达规避与台词规则 |
| `POST /api/variants` | 主题变体 |
| `POST /api/full-story` | 选中变体的完整剧情 |
| `POST /api/animation-plan` | 首尾帧动画生产包 |
| `POST /api/refine-character-reference` | 使用上传图片修正角色参考描述 |
| `POST /api/generate-character-reference-images` | SSE 流式生成角色参考图 |
| `POST /api/generate-shot-frame-image` | 生成单镜头首帧或尾帧候选图 |

## 7. 配置说明

所有可提交的配置示例都在 `.env.example`。`.env` 已被 `.gitignore` 忽略，交接时不得复制密钥到文档、日志、测试夹具或 Git。

### 7.1 LLM 与视频理解

- `MIMO_*`：MiMo 地址、key、各阶段模型、媒体模式、原生视频大小、FPS、token、thinking 和 JSON 重试。
- `QWEN_*`：Qwen 地址、key、各阶段模型、媒体模式、像素预算、token、thinking 和 JSON 重试。
- 当 Qwen 已配置时，工作流默认优先使用 Qwen；未配置时回退 MiMo；两者都未配置时使用演示数据。
- 分析、还原、视觉规则、人物参考修正属于媒体阶段。若把 Qwen 媒体阶段覆盖为已知纯文本 `*-max` 模型，代码会回退到该阶段默认视觉模型。
- 页面“模型设置”可为每个阶段覆盖 provider、模型名和 token 上限；覆盖值保存在浏览器 `localStorage` 的 `directorModelOverrides`。

### 7.2 图片生成

- `JIMENG_*`：即梦/Seedream API 地址、key、模型、尺寸、格式、字段名、水印、数量和超时。
- 国内火山方舟和 BytePlus 国际站的地址、key、模型 ID 必须配套，不能混用。
- 生成图片写入 `public/generated-images/`，该目录被 Git 忽略。

### 7.3 视频生成

- `VIDEO_HTTP_*`：图片/视频 endpoint、视频模型、API key、preset、轮询和视频参数。
- 内置 preset：`modelark_content_generation`、`kling_image_to_video`。
- 自定义供应商可复制 `workers/generic-http-worker.example.json`，通过 `bodyTemplates` 和响应字段映射适配。
- 生成视频写入 `public/generated-videos/` 或 production workspace 的 `outputs/`，均不应提交到 Git。

### 7.4 负面提示词数据与供应商传递

不要再从“用户未声明某特征”推导渲染负面词。`visualGuardrails` 的职责已拆成四类：

- `positivePromptBoundary`：只审查正向提示词是否越过用户授权；
- `sourceSimilarityRules`：在主题、故事和分镜层规避原片表面表达；
- `dialogueRules`：约束台词和角色说话方式；
- `renderNegativePrompts`：只存在于 `animationPlan.shotPlan[].negativePrompts.image/video`，并且必须与当前镜头直接相关。

每个 render negative 条目包含 `text`、`appliesTo`、`triggerEvidence[{sourcePath,evidence}]`、`reasonCode`、`priority`，可选 `enabled`。图片/视频数组允许为空；任务队列只保留当前媒介中 `enabled !== false` 的条目，同时写入 `negativePromptEntries`、`compiledNegativePrompt` 和兼容字段 `negativePrompt`。旧的 `commonNegativePrompt`、`visualBible.negativeVisualRules`、`sceneReferencePrompts[].negativeSceneRules` 与 `shot.negativePrompt` 不会自动迁移成有效渲染负面词。

供应商支持矩阵：

| 路径 | 独立字段 | 实际策略 |
| --- | --- | --- |
| Kling preset | `negative_prompt` | `native_negative` |
| 通用默认 HTTP | `negativePrompt` | `native_negative`，由适配端确认字段有效 |
| 自定义 body template | 取决于模板 | 显式映射后为 `native_negative`，否则 `not_supported` |
| ModelArk / Dreamina 视频 | 无 | 仅高优先级身份冲突可转为正向身份锁定，标 `positive_constraint`；其余忽略 |
| 即梦 / Seedream 图片 | 无 | 同上；不得伪造独立 negative 字段 |

当当前图片或视频负面数组为空时，worker 不发送空负向字段，回执标记 `appliedMode=not_applied`。

通用 worker 回执中的 `negativePromptDelivery` 会说明 `appliedMode`、实际字段、`compiledNegativePrompt`、应用文本和忽略情况；`requestPreview` 会遮盖 API key、token、data URL/base64 与敏感 URL 查询参数。验收供应商传递时应看回执和实际 request snapshot，不能只看 LLM 输出。

## 8. 生产流水线 CLI

从页面导出视频任务队列 JSONL 后，推荐按以下顺序执行。

生成工作区：

```bash
npm run plan:video -- ./视频任务队列.jsonl --root ./production/V1 --workspace
```

如果已有人工或历史产物，扫描并释放依赖：

```bash
npm run plan:video -- ./视频任务队列.jsonl --root ./production/V1 --workspace --scan-existing
```

只验证任务依赖和落盘协议：

```bash
npm run exec:video -- ./production/V1 --provider mock --all
```

真实执行前预检：

```bash
npm run preflight:video -- ./production/V1 --strict
```

一键生成和合成：

```bash
npm run make:video -- ./production/V1 --config ./provider.json
```

查看报告：

```bash
npm run report:video -- ./production/V1
```

任务状态主要为 `pending`、`ready`、`blocked`、`done`、`failed`。command worker 必须读取 request JSON，把非空产物写到指定 `outputPath`；失败时执行器会生成 `<output>.error.json`。修复后用 `--retry-failed` 重试。完整协议见 `docs/video-worker-protocol.md`。

## 9. 数据与状态

- 浏览器保存：创作者画像 `directorProfile`、阶段模型覆盖 `directorModelOverrides`。
- 浏览器内存保存：当前视频采样帧、各阶段输出、候选图片/视频选择；刷新页面不会恢复整套创作会话。
- 服务端持久化：生成图片和单镜头视频；没有数据库。
- 导出文件：完整方案 JSON、当前生产包 JSON、测试包 JSON、任务队列 JSONL、视频模型 Markdown 文本。
- production workspace：`production-run.json`、`prompts/`、`requests/`、`outputs/` 和执行回执。

生产产物可能占用大量磁盘，当前没有自动清理、配额或生命周期策略。清理前先确认文件不再被生产包或任务状态引用。

## 10. 已知边界与风险

1. 音频没有自动转写。视频理解主要依赖视觉内容和用户补充文本，准确对白需要用户粘贴字幕/转写或新增 ASR 阶段。
2. 浏览器关键帧采样可能漏掉快速剪辑、瞬时动作和声音设计；原生视频超限或 provider 不支持时会自动回退关键帧。
3. 前端生产控制台尚未实现。整片任务仍需导出 JSONL 后在终端执行、检查和重试。
4. 本次交接未用真实账号完成“图片 → 首尾帧视频 → 最终 mp4”验收。现有测试使用本地模拟供应商，证明协议和编排可运行，不证明真实账号权限、额度或字段映射正确。
5. 质检目前偏基础，主要检查文件存在、可解析、非 mock 等；尚不能稳定识别角色漂移、闪烁、首尾帧偏离、字幕/对白错误。
6. 最终剪辑以基础 ffmpeg 合成为主，转场、统一字幕、音乐音效、安全区和发布级编码仍需完善。
7. 任务恢复能力有限：缺少运行锁、checksum、明确的 `running/skipped` 生命周期和成本/并发控制。
8. `public/app.js`、`src/validation.js` 和通用 worker 文件较大，继续扩展前建议先拆模块，避免 UI 状态与业务逻辑进一步耦合。
9. 服务没有用户体系、鉴权、速率限制或持久化会话，当前定位是本地单用户工具，不应直接暴露到公网。
10. `.env` 包含真实服务配置，排查问题时不要在终端或 issue 中打印完整环境变量和供应商响应。
11. 供应商对 negative prompt 的支持不一致。验收时必须检查 worker 回执的 `negativePromptDelivery` 和脱敏 `requestPreview`；不能仅凭队列或 LLM 输出判断已经生效。

1. 强化跨镜连续性：角色/资产参考、上一镜尾帧、下一镜首帧、服装与空间锚点。
