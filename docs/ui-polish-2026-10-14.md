# 页面 UI 精修（2026-10-14）

用户反馈页面「部分设计效果很丑」，举了三处：分镜页的「改编说明 / 修订与引导说明」、A04 镜头卡、「角色事实与本片设计」，并说明还有很多。

## 勘察

全部只读、不花钱：

- 演示服务（模拟模型）把「从剧情开始」和「从参考视频开始」两条流程各跑一遍，用无界面 Chrome 逐块截 2 倍图。
- 用用户当时那个 Run（套被子）的真实分镜与剧情数据，在一个本地渲染页里调用 `public/storyboard-render.js` 与从 `app.js` 取出的渲染函数，重现截图里的样子。

问题是系统性的：

1. **默认字号漏网。**「角色事实与本片设计」「改编说明」「修订与引导说明」、完整剧情的「完整配角设定」直接输出裸 `<p>`，没有任何样式，退回浏览器默认 16px——比周围大一号，也是截图里大段文字墙的直接原因。
2. **其余正文太小。** 卡片正文普遍 10–11px，标签、徽章 8–9px。
3. **卡片套卡片加空白。** 镜头卡里的节拍复用了剧本场次的 `.scene`，它给「S1」方块留了 53px 左边距，节拍没有方块，左边空一大块；镜头卡 → 节拍卡 → 再套边框，三层框。
4. **「<b>标签：</b>内容<br>」与分号串。** 设定、一致性标签、禁止变化都用「；」「 / 」串成一长串。
5. **修订与引导说明混在一起且有重复。** 服务端的 `editorial.guidance` 是「初审引导 + 每条修订说明 + 终审引导 + 最后一轮审阅报出的问题」（`src/storyboard-workflow.js`），页面先列修订条目、再把 guidance 整串照排，修订说明出现两次，终审仍指出的问题也和普通引导分不开。
6. **角色参考卡看不到参考图本身**，只有「已添加人物参考图」徽章。
7. **橙色用得太多**：人名、时间段、小标签都是橙色，像警告或链接。
8. 零散：剧情入口时流程条只有 2 步却按 5 列排；导演助手栏打开时分场页大标题被挤成一字一行；首页剧情模式左卡下半截空白；勾选框是系统蓝；剧情体检显示字段名 `emotionalPayoff`；Georgia 只有旧式数字（「A01」「2.0」像小写）；角色边界显示 `sourcePath=creatorProfile.fixedCharacter；evidence=…`；视频画幅下拉固定 110px，「16:9 · 横屏」被截断，剧情入口那条长选项把「剧情时长」挤成竖排。

## 改了什么

保留原有视觉身份（米色纸面、墨色、橙色强调、衬线大标题、黑底摘要条），只修可读性与信息结构。

- **`public/styles.css`**：`:root` 加字号阶梯（12/13/14/16）与语义色；正文最小 12px；小节里的裸段落给默认样式（`:where()` 零特异性，不压过已有 class）；徽章统一一个形状、各自保留原色调；小节标题改成带橙色短竖条的 13px；新增 `.kv`（左标签右内容）、`.chips/.chip`、`.mini-card/.card-grid` 三个小部件；`.rule` 左列定宽，标题本身就是长句的清单用 `.stacked` 上下排；衬线字体栈换成 `Iowan Old Style` 起头并开 `lining-nums`；大标题字号按容器宽度缩放（容器查询单位）；流程条列数跟可见步数走；剧情模式故事输入框吃掉左卡剩余高度（与 09-10「左右卡等高」的做法一致）；勾选框用品牌色。
- **`public/storyboard-render.js`**：数据条压成一行；删掉「角色事实与本片设计」（见下一节）；场景、道具改成属性表；镜头卡的节拍改成时间轴（左列时间，右列地点与出镜人物 → 画面 → 动作 → 台词 → 声音），结束状态与验收标准用 ✓ 清单，按钮与提示收成一行；改编说明原文与改成并排、理由在下；修订与引导说明按来源分组。
- **`public/fact-sheet.js`**（新增）：`dotList()`（多条短事实连成一行、圆点隔开）与 `factSheet()`（左列名字、右列属性的属性表），分镜页与完整剧情页共用。
- **`public/app.js`**：角色参考卡左侧显示 Plan 里已有的参考图（只认 `data:image/`；显示了图就不再另挂「已添加人物参考图」徽章），右侧外观、一致性标签、禁止变化（圆点隔开）、参考图吸收与两个操作按钮；完整剧情的配角改成属性表、场次内部用 `.kv`；角色边界的 `scope` / `evidenceLevel` 枚举与触发证据路径显示中文（认不出的照原样）；`resultHeader` 的标题改为转义（原来模型写的剧情 / 分镜标题直接拼进 HTML）；生成角色参考图的「+」圆按钮改成带字的按钮。
- **`public/story-review-metrics.js`**：在 `PROMISE_SOURCE_FIELDS` 旁加 `PROMISE_SOURCE_LABELS`，剧情体检的承诺来源显示中文。

### 删掉「角色事实与本片设计」，标签云改成属性表（用户看过第一版之后）

第一版把这一块做成三张并排小卡、每条事实一个胶囊标签。用户看过觉得不好看，并指出上面已经有角色参考卡，这一块是重复的，决定直接删掉。

删掉之前核对过：这一块显示的是分镜登记表里的身份、与主角的关系、剧情作用、外观、性格、说话，加上本片分镜新设计的外观（`designedDetails`）。关系、性格、说话在完整剧情页的「完整配角设定」里照样有；新设计的外观已经写进角色参考卡的外观描述（`appearancePrompt`）里。删掉之后唯一看不到的，是「哪几条外观是这一版分镜新加的」这个标记。字段本身（`visualDesign.characters[].designedDetails`）照常生成、签发，没有动。

同一个原因（长短不一的胶囊堆成一团显得乱），角色参考卡的一致性标签、禁止变化，以及完整剧情的配角、分镜页的场景与道具，都改成左列名字、右列属性、同一属性里用圆点隔开的写法。只有镜头卡节拍里的出镜人物还用小标签（都是很短的人名）。

### 修订与引导说明怎么分组

全部是逐字比较，没有语义判断：

- 「审阅后的修订」：`editorial.repairs`，每条带状态徽章（已修订 / 本条未采用 / 保留原文）；已修订的显示改了几处，未采用的显示服务端给的原因。
- 「终审复查仍指出的问题（没有再修订）」或「审阅指出、没有改正文的问题」：`(finalReview || initialReview).items` 的 `reportedProblem`，**只取 guidance 里真有的**，保证显示的原文集合与原来一致。
- 「引导说明」：guidance 去掉与修订说明、上一组逐字相同的条目，并去重。
- `blockedIssues` 单独成组，标题是提示词里的原意「无法在授权范围内解决的问题」。
- 演示与旧 Plan 没有审阅结构时退回一个列表；全空时仍是「本轮没有额外修订说明。」

## 没有改

字段、提示词、Schema、校验、任务、lineage、Artifact 都没动。所有 `data-*` 钩子保留；`updateShotVideoProviderUi` 会改写镜头按钮的 `textContent`，所以按钮仍是纯文字；契约要求必须显示的提示（被拦重试、边界补写、「仅供参考，系统不会自动执行……」等）逐字保留。模型设置弹窗与导演助手只随字号调整，结构没动。
