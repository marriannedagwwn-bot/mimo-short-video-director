# 生产化动画工作流后续待办

这个文档用于记录“生产化动画工作流”的后续完善方向。当前项目已经具备基础闭环：MiMo 生成动画生产包、导出 JSONL 队列、生成 production workspace、HTTP worker 生成图像/首尾帧视频、本地质检和 ffmpeg 合成。但它还不是完整产品化状态，后续约有 30%–40% 的工作需要补齐。

## 以后怎么让 Codex 切换回来继续做

可以直接这样说：

> 继续完善生产化动画工作流，按照 `docs/production-animation-workflow-todo.md` 的待办推进。先检查当前代码和已完成项，然后从最高优先级开始实现、测试并提交。

如果你想限定范围，可以这样说：

> 只做生产化动画工作流的供应商配置和预检完善，参考 `docs/production-animation-workflow-todo.md`。

或者：

> 只做生产化动画工作流的前端可视化进度，不改底层 worker。

## 还没完善的核心问题

### P0：供应商配置还不够产品化

目标：让用户不需要理解 worker 协议，也能稳定接入具体图像/视频模型。

待办：

- 做一个清晰的 `provider.json` 配置向导或模板选择机制。
- 为常见供应商拆出配置模板：
  - 图像生成
  - 首尾帧/关键帧视频生成
  - 异步任务轮询
  - base64 返回
  - mediaUrl 返回
- 在页面或 CLI 中验证配置是否可用：
  - endpoint 是否能访问
  - API key 是否有效
  - 返回字段是否能被解析
  - 图片/视频文件是否真的写入成功
- 将当前偏底层的错误信息转成用户能直接处理的提示。

验收标准：

- 用户只需要填写 endpoint、key、model 和字段映射，即可跑通一条测试 shot。
- 配置错误时能明确指出是鉴权、字段映射、轮询、下载还是产物格式问题。

### P0：生产过程缺少前端可视化控制台

目标：用户不需要一直在终端执行命令，也能看到整片生产进度。

待办：

- 在 story 页面增加“生产化制作”入口。
- 展示 production workspace 状态：
  - ready
  - blocked
  - running
  - done
  - failed
- 展示每个任务的产物：
  - 角色参考图
  - 资产图
  - 首帧
  - 尾帧
  - 镜头视频
  - 最终成片
- 支持从页面触发：
  - 生成 workspace
  - preflight
  - 执行 ready 任务
  - 重试 failed 任务
  - 查看 report
- 显示失败原因和下一步建议。

验收标准：

- 用户可以从页面完成“导出队列 → 预检 → 执行 → 看结果 → 重试”的主要流程。

### P0：缺少真实供应商端到端样例

目标：不仅 mock 通过，还要至少用一个真实图像/视频供应商跑通。

待办：

- 选择一个实际要接的图像生成模型。
- 选择一个实际要接的首尾帧视频模型。
- 写对应 provider config。
- 用一个 1–2 个 shot 的小样例跑通：
  - 图像生成
  - 首尾帧视频生成
  - 本地质检
  - 最终合成
- 记录真实响应格式和常见失败。

验收标准：

- `npm run make:video -- ./production/<variant> --config ./provider.json` 能生成真实 mp4。

### P1：镜头连续性控制还不够强

目标：减少角色长相漂移、服装变化、场景跳变。

待办：

- 将角色参考图、资产图作为后续首尾帧生成的强输入。
- 给每个 shot 增加连续性字段：
  - characterReferenceInputs
  - assetReferenceInputs
  - previousShotEndFrame
  - nextShotStartFrame
- 支持把上一镜尾帧作为下一镜首帧参考。
- 在 prompt 中固定：
  - 主角外观
  - 服装
  - 场景空间关系
  - 色彩风格
  - 镜头语言
- 在质检阶段检查明显漂移。

验收标准：

- 连续 3–5 个 shot 生成后，主角身份、服装、画风和空间关系基本稳定。

### P1：质检还比较粗

目标：让系统能判断某个镜头是否需要重跑，而不是只看文件是否存在。

待办：

- 增加视频质检指标：
  - 是否黑屏
  - 是否过短
  - 是否无法播放
  - 是否明显闪烁
  - 是否缺首帧/尾帧对应关系
  - 是否角色严重漂移
  - 是否字幕/对白不符合要求
- 质检失败后自动标记 failed，并给出重跑建议。
- 支持单个 shot 重跑而不影响其他完成产物。

验收标准：

- 失败镜头能被定位到具体 task，并能通过 retry failed 只重跑问题镜头。

### P1：最终剪辑还只是基础合成

目标：最终成片接近可发布短视频，而不是简单拼接。

待办：

- 支持转场策略。
- 支持统一字幕。
- 支持背景音乐和音效层。
- 支持片头 hook 和结尾仪式化动作强化。
- 支持统一分辨率、码率、帧率。
- 支持安全区和移动端竖屏预览。

验收标准：

- 最终输出是完整竖屏短片，具备字幕、节奏、转场和基础声音设计。

### P2：任务状态和产物管理需要更稳

目标：长流程中断后能恢复，不重复浪费生成成本。

待办：

- 更清晰地区分：
  - pending
  - ready
  - running
  - done
  - failed
  - skipped
- 避免运行中断导致状态卡住。
- 增加任务锁或运行 ID，防止重复执行同一个 task。
- 对产物做 checksum 或 metadata 校验。
- 支持清理某个 task 的输出并重置状态。

验收标准：

- 中途中断后重新执行，不会重复生成已完成产物，也不会把坏产物误判为 done。

### P2：成本和批量控制

目标：避免一次性把整片任务全部打出去导致成本不可控。

待办：

- 增加 dry-run 成本估算。
- 支持只执行前 N 个 shot。
- 支持按能力执行：
  - 只生成参考图
  - 只生成首尾帧
  - 只生成视频
  - 只做后处理
- 支持并发数限制。
- 支持失败率过高时自动停止。

验收标准：

- 用户能先低成本验证 1 个 shot，再扩大到整条视频。

## 建议实施顺序

1. 先做供应商配置产品化。
2. 再做真实供应商端到端样例。
3. 然后做前端生产控制台。
4. 再加强连续性和质检。
5. 最后完善最终剪辑、成本控制和恢复能力。
