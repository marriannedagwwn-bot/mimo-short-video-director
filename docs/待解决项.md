## 1. 镜头动作过载，源头在 Full Story 而不是分镜

**状态**：已定位根因，未决定怎么改。

**现象**：定向修订对某些镜头永远通不过净预算闸门（`删 ≥ 加`），无论重试多少次。

**证据**（2026-09-07 真实回放，《天台上的纸飞机》）：

- 终审自己判 A03「12 秒内要完成折、画、飞、回信、接、再折再飞、猫追影、按发笑等多个事件，
  动作链过长」+ `ai_risk`，**同时**又给这一镜派了 6 条 issue 和 2 条 upgradePath，合计要加 7 样东西
- 修订模型**如实照做并如实报数**：第一次 A03 删3加7、A04 删1加2、A06 删3加4
- 带算术诊断重试一次后 **A04 与 A06 都修好了**（删2加2 / 删4加4），只有 A03 从加 7 降到加 6 仍超支
- 两次 provider 调用、19 分钟、58018 token，最终 fail closed

**根因不在修订，在上游**：A03 的 12 秒来自 `fullStory.sceneScript` 的 S3（`00:18-00:30`），
而 S3 的 `visibleAction` 是全片最长的一条（163 字），塞了约 14 个动作：

> 抽白纸 → 折纸飞机 → 画哭脸 → 侧身飞出 → 划过夕阳 → 对面飞回 → 接住打开 →
> 嘴角上扬 → 又折一架 → 画太阳 → 再飞过去 → 猫追影子蹦跳 → 风吹乱头发 → 按住头发眯眼笑

**修订在架构上就修不了它。** 镜头骨架由 `deriveDirectShotSkeleton()`（`src/direct-shot-timeline.js`）
从 Full Story 场次**确定性派生**，修订只能改 7 个可写字段，**动不了 `durationSeconds`、也不能拆场**。
它只能在固定的 12 秒里搬动作，而 12 秒本来就装不下这些。

**方向（未验证）**：在 Full Story 阶段就约束单场动作密度——要么写少一点，要么把 S3 拆成两场。
`§2.10` 已有「生活质感」「萌点必须是大动作」等生成约束，但**没有任何一条约束单场动作数量**。

**已经排除的做法（都试过或已论证不可行）**：

- ~~在终审侧加硬闸门，不许它给过载镜开净增方子~~ —— **2026-09-07 实测有害，已回退**。
  终审没有重试，硬闸门架在它自己的输出上就等于整个阶段出不了报告：三次真实调用全失败，
  而此前它是能出报告的（09:50 那次 493 秒、7.03 分）。
- ~~把「补写既有事实」从净预算里豁免~~ —— 实测推翻。A03 那两条 `prop_state_break` 的修法是
  「把纸飞机放在书包上」，**是货真价实的物理动作**，豁免它等于放宽闸门（§5 第 1 条）。
  唯一构造上非动作的 `dialogue_not_in_prompt` 只值 1 个额度，救不了 A03（额度 4 < 加 6）。
- ~~让模型自报 `actionComplexity`~~ —— `CLAUDE.md:343` / `AGENTS.md` / 实施计划三处明文禁止：
  把判定权还给模型，正是净预算当初要拿走的东西。
- ~~拿维度分数当门槛~~ —— 同上三处禁止，单维分辨力最差（两个模型评同一份能差 ±1.0）。

**不得因为某个输入通不过就放宽净预算闸门。** 它在真实数据上是有效的：三次真实调用全都

## 2. `ModelPipelineError` 吞掉供应商原文

**状态**：已定位到具体一行，未改。

**证据**：`src/server-error.js` 的两个分支口径不一致——

| 分支 | 有没有带出供应商原文 |
| --- | --- |
| `ModelResponseError`（`:176`） | ✓ 调 `providerRawAttempt` + `describeProviderError({payload: error.raw})` |
| `ModelPipelineError`（`:22`） | **✗ 只回 message / diagnostics / attempts** |

coordinator 抛的正是 `ModelPipelineError`，所以**凡是走 coordinator 的阶段，供应商自己的
错误消息一律被吞掉**：定向修订、Full Story、Animation Plan 一直如此。

实际代价：2026-09-07 一次重试被 HTTP 400 拒绝，350 字节的错误原文存在内存 `AttemptStore` 里
（`rawOutputRef` 指着它），但响应里 `details: []`、`providerError: null`，
**根本无法判断 400 的原因**，调查就此中断。

这与 `§5.1`「原文必须真的显示出来」是同一条规则，而那条规则的正文里就在讨论这个文件。
修法很可能就是给 pipeline 分支补上同样两个 helper（都是现成的）。

## 9. 旧 Artifact 走候选对照评审会得到归属错误的 502

**状态**：已定位到具体一行，未改。

**现象**：拿一份 2026-09-06 之前导出的生产包去调 `POST /api/story-candidate-review`，
返回 **HTTP 502**，消息是「**模型输出**未通过校验：themeVariants Story Candidates 结构校验失败：
`/variants/0/highValueBeatMapping/0/failureSignal` 缺少必要字段……」。

两处都不对：

- **归属错**。那份 themeVariants 是**请求输入**，不是本阶段的模型输出。用户看到「模型输出未通过校验」
  会去查模型、查供应商，而实际上错在自己传的包。
- **状态码错**。客户端传了不合契约的输入应当是 4xx；502 指向上游模型服务。

**根因**：`createStoryCandidateReview`（`src/workflow.js`）第二行就是
`ensureOutputContract(themeVariants, "themeVariants")`。这个调用**本身是对的**——
注释写着「评审对象必须先是一批合法候选，否则报告没有意义」——错的是它抛出的
`OutputContractError` 被原样上抛，而那个类型的语义就是「模型输出不合契约」。

**修法已有逐字先例，在同一个文件里**：`createAnimationPlanRevision` 的 `report` 同样是请求输入，
那里用 `try/catch` 包住校验并转成 `InputError`，消息写「report 不是这份 animationPlan 的合法终审报告：…」，
`details` 原样带上。候选评审这条路没接。

**实际代价**：`failureSignal` 与 `transformationProof` 的 `{source, replacement}` 都是 2026-09-06
之后才加的必填字段，所以**在那之前导出的候选一律评审不了**。而评审恰恰是只出报告、不进 lineage、
不改任何东西的阶段——它是最应该能读历史数据的那一个。

**尚未决定的部分**：只修归属与状态码，还是同时让缺新字段的旧候选降级通过（同 §2.4 已下线方言那种
精确白名单）。后者是**契约变更不是 bug 修复**，需要先想清楚哪些字段可缺、缺了之后评审投影怎么处理，
因此没有一并做。

**不得**为了让旧包通过就放宽 `ensureOutputContract` 或跳过输入校验（§5 第 1 条）。
