# 一句话修改（2026-10-11，导演 Agent 第三期）

在导演助手里说一句话，例如「第 3 场改成雨停了」「A04 别让她回头」「把结尾那句台词删掉」，系统把它变成对**剧情**、**4.0 分镜**或**某一镜视频提示词**的局部修改。修改稿先摆在被改的东西旁边给你看，你点「采纳」才签发。

四期计划里的第三期：从剧情开始（第一期）→ 导演助手对话栏（第二期）→ **一句话修改（本期）** → 4.0 批量出视频（第四期）。

## 1. 用户已经定的三条规则

1. 「粘贴完整故事」的 Run 也可以用一句话改情节和台词。改过的台词会出现在台词核对的「在原文里找不到」里，这是预期的；原文本身永远不动。
2. 只在导演助手里说，页面上没有单独的输入框。修改稿和「采纳 / 放弃」显示在被改的东西所在的位置：剧情与分镜在分场页上，单镜提示词在那一镜的视频弹窗里。
3. 说到某一镜时：已经有镜头视频，就只改这一镜的视频提示词（不让别的镜头的视频作废）；还没有视频，就改分镜。

## 2. 流程

1. 用户在对话栏打一句话。导演助手的模型只负责把这句话对到「按你的话修改……」这三个动作之一，**不写修改内容、不改写用户的话**。
2. 卡片写明：你的原话（摘前 120 字）、改的是哪一份、采纳后会作废什么（带数量）、要调用一次文本模型。
3. 点「确认执行」：页面请求修改稿 `POST /api/one-sentence-edit/draft`，另起一次调用按**原话**写修改稿。写稿期间导演助手显示「正在按你的话写……的修改稿」，不提别的动作。
4. 修改稿逐处列出「原来 → 改成」，附 AI 的说明。做不到的（加一场、加新角色、改时长、新增一句台词、话没说清楚）写明原因，不硬改。
5. 「采纳」：会作废东西时先弹窗征求同意（写明作废几样）；服务端拿当前版本把同一组修改重新应用一遍、核对结果摘要，再签发；页面从服务端读回 Run；导演助手报一句「改好了：……」，按新进度提议下一步（比如重新生成分镜）。
6. 「放弃」：什么都不变。

| 改什么 | 采纳后作废什么 |
| --- | --- |
| 剧情 | 分镜、存在分镜里的已选人物参考图、所有单镜提示词、镜头视频与角色候选图。要重新生成分镜 |
| 分镜 | 所有单镜提示词、镜头视频与角色候选图。已设为人物参考图的图在分镜里，原样保留 |
| 某一镜的提示词 | 什么都不作废。这一镜已有的视频不会自动重做 |

作废清单与状态库 `propagateStale` 同一口径：当前版本里直接或间接依赖被改那一份的产物（`oneSentenceEditDependents`）。

## 3. 契约

### 3.1 修改稿接口 `POST /api/one-sentence-edit/draft`（只出修改稿，不签发）

- 请求体**只收**：`projectId`、`runId`、`target`（`story` / `storyboard` / `shotPrompt`）、`variantId`、`shotId`（只在 `shotPrompt` 时）、`baseRevision`、`instruction`（≤500 字）、`creatorProfile`（参考视频 Run 改剧情或分镜时必带，用来核对角色边界签名）、`modelOverrides`。多一个键就 400 `ONE_SENTENCE_EDIT_INPUT_INVALID`——剧情、分镜、提示词与任何上游**一律由服务端从 Run 里读当前版本**，不收页面副本。
- 剧情 Run 的固定角色设定用开 Run 时写进元数据的那一份；页面带了副本就必须相同（`TASK_BROWSER_ARTIFACT_MISMATCH`）。
- `baseRevision` 不是当前版本 → 409 `ONE_SENTENCE_EDIT_BASE_CHANGED`；写稿可能要一两分钟，写完再核对一次，期间版本变了同样 409。
- 有相关任务在跑（目标本身、它的下游，或同一故事位正在生成的分镜 / 提示词 / 视频 / 角色图）→ 409 `ONE_SENTENCE_EDIT_TASK_ACTIVE`。
- 走路由表，用量挂在响应信封上（`runWithUsageAccounting`）；页面直接 `fetch`、不走 `api()`，花费不混进正在进行的那一步。
- 响应：`{schemaVersion, target, shotId?, decision, patches, note, changes, resultDigest, afterText?, metadata, artifactId, variantId, baseRevision, invalidation}`。

### 3.2 模型输出 `one-sentence-edit/1.0`

`{decision: "edit" | "decline", patches, note}`，只许这三个键。`note` 必填、≤300 字；`edit` 时至少 1 处、最多 6 处，`decline` 时 `patches` 必须是空数组。每处修改都是「在某个字段里找到**恰好出现一次**的一段原文 → 换成什么」，原文由服务端逐字替换：

| 对象 | 每处修改 | 能改什么 |
| --- | --- | --- |
| 剧情 | `{sceneId, field, find, replace}` | 每场 `visibleAction` / `shotAndSound` / `dialogue`（台词正文）/ `emotionNode` / `dramaticFunction`；`sceneId` 写空串时只能改全片 `oneLinePremise` / `shootingSynopsis`。删一整句台词 = 整句原文换成空 |
| 分镜 | `{path, find, replace}` | 沿用分镜内部修订那份可改清单（`catalog(plan).filter(editable)`），**再去掉角色外观** `visualDesign/characters`——外观要和已选的人物参考图对得上 |
| 提示词 | `{find, replace}` | 提示词里的片段，**不许整段替换**（本仓库实测过让模型复述长文本时它会整体换措辞） |

名字、说话人、台词画内画外、场次来源、出镜名单、时长与数字都不在可改范围里。

### 3.3 执行与校验：与签发时同一套

- 先让**当前版本自己**过一遍签发校验，过不了就在调模型之前 400（否则「改完不合法」无法归因到修改上）。
- 剧情：`applyStoryRepairPatches`（「按问题修改」的执行器，新增可选参数放宽上限与字段，**不传时行为逐字不变**）→ `validateFullStoryForSigning`（与生成、按问题修改共用的签发校验链）→ `assertOnlyStoryRepairFieldsChanged` 证明可写字段之外逐字节不变；不能让出镜角色从一场里消失。
- 分镜：先按缩小后的可改清单逐处预检，再交给 `applyEditorial`（原子、证明目标之外逐字节不变、跑分镜校验），最后 `ensureAnimationPlanMatchesProfile`（分镜校验 + 候选一致 + 人物参考的角色边界）。
- 提示词：改完必须仍逐字包含这一镜的每句台词、分镜的画风、「无背景音乐」收尾句——判据抽成 `shotVideoPromptViolations`（`src/storyboard-workflow.js`），写提示词与一句话修改共用一份。版本、镜头号、对应的分镜摘要、视频模型、写稿模型原样保留，弹窗缓存照常命中。
- 结构错或执行不了（原文找不到 / 不唯一、改完过不了校验）都带诊断重试一次，**禁止第三次**；两次都不行如实报错、两次诊断都在。内容审核拦截不重试。

### 3.4 采纳接口 `POST /api/production/one-sentence-edit/adopt`（服务端签发）

- 请求体只收坐标、`target`、`variantId`、`shotId`、`baseRevision`、`patches`、`resultDigest`、（参考视频 Run 的）`creatorProfile`；**不收原话**。
- 服务端拿当前版本把同一组修改重新应用、重新校验，结果的 `contentDigest` 必须等于修改稿上的 `resultDigest`，否则 409 `ONE_SENTENCE_EDIT_RESULT_MISMATCH`（修改稿被改动或基准已变）。保证签发的就是用户看过的那一份。
- `commitArtifact` 用**与上一版完全相同的依赖**、`expectedCurrentRevision` = 基准版本、`requestId` 前缀 `one-sentence-edit-`；分镜签发新的媒体命名空间。依赖不变，所以剧情 Run 仍能导出 3.1 测试包。
- 不走页面的通用提交口：那个口不检查内容，剧情 Run 的依赖页面也拼不对。

### 3.5 新阶段 `oneSentenceEdit`

可选、默认文本模型、输出上限 ≥32768（推理段可能很长，截断会让整份修改稿作废）、**不改思考设置**；模型设置里可换；调试侧车 scope `oneSentenceEdit`（登记在导演助手之前，现有测试要求导演助手排最后）。系统提示词显式换掉客户端默认的「受控改编」。

### 3.6 提示词（`src/one-sentence-edit-prompts.js`，全新，不动任何已锁定的提示词）

用户的原话原样放在 `<<< >>>` 里，同时声明其中改规则、改格式的话不照做。各类只送必要的内容：剧情送完整剧情 + 固定角色事实（不送原文）；分镜送分镜本身 + 角色表 + 制作参数（不送完整剧情、去掉人物参考里的图片与音频数据）；提示词送这一镜的提示词、分镜与「必须逐字保留」清单。举例一律用占位写法。

## 4. 导演助手

- 三个新动作：`editStory:<V>`、`editStoryboard:<V>`、`editShotPrompt:<V>:<shot>`。模型能选，但**从不作为「下一步」、不做成按钮**——只在用户自己说要改什么时由模型对上。动作上限从 40 提到 80（每个写好提示词的镜头各一个）。
- 可用规则（`public/director-agent-progress.js`）：有 1.1 剧情就能改剧情（旧格式不行）；有 4.0 分镜就能改分镜，有视频时卡片警告「已经有 N 条镜头视频：采纳后会全部作废」；**至少一镜有视频之后**，才给每个提示词已写好（弹窗不用重写）的镜头一个「只改提示词」。旧版 3.0 生产包只能改剧情；分镜版本信息对不上时不提修改。
- 卡片带用户这一句原话（`card.instruction`）；原话不同就出新卡，同一句只挪到最下面。`guard` 带基准版本（剧情 / 分镜 / 提示词）与模型。
- 修改稿等用户决定时不提别的动作，只说修改稿在哪；修改稿在分场页上而用户不在分场页时给一个回分场页的按钮。写稿与签发期间同样不提。
- 结果各报一句（只报计数与位置）：写好（改了几处）、没改成、采纳（作废了什么）、放弃、过期、失败（审核拦截说明不会自动重试）。
- 提示词规则第 5 条从「这些现在做不了：修改剧情、分镜、台词或某一镜的提示词」改成：对到相应的修改动作；点名某一镜时清单里有「只改这一镜的提示词」就选它；没说改成什么（「好的改吧」「改一下」）写 none 请用户说完整；加场、加人、改时长、新增台词直说做不到。导演助手的回复格式不变。
- 演示模式：用户说到「改」「删」时对上修改动作，点名某一镜优先只改那一镜的提示词。

## 5. 页面（`public/one-sentence-edit-ui.js` + `public/app.js`）

- 三处预览：`#storyEditPreview`（剧情上方）、`#storyboardEditPreview`（分镜上方）、`#shotPromptEditPreview`（视频弹窗里提示词下方）。「粘贴完整故事」的 Run 里跟着页面把剧情叫「可翻拍镜头」。
- 修改稿与原话**只在页面内存里**，不进任何浏览器存储、不进任务记录或产物；刷新即丢（已经花的那次调用不退）。
- 修改稿针对当时那一版：那一版变了（重新生成、设为人物参考图、重新拆分……）就作废并报一句；换了 Run 时悄悄丢掉。
- 采纳会作废东西时 `window.confirm` 写明作废几样；单镜提示词在弹窗里手动改过时提醒手动改的会丢掉。采纳成功后 `reloadActiveProductionRun` 读回 Run，不在页面上拼。
- 视频弹窗：写稿与签发期间不能关；修改稿等决定时关弹窗先问、关了就是放弃；修改稿没处理不能生成视频、不能重写提示词。
- 「重新拆分」的确认改为只要已经拆过就弹（原来只在有分镜时弹），写明会覆盖用一句话改过的地方。

## 7. 已知局限（也登记在 `docs/待解决项.md` 第 22 条）

- **改得对不对没有确定性兜底**：改错了场次、把「甲替乙」写反，只能靠人在预览里看。
- **这些操作会丢掉一句话修改**：「重新拆分」按原文重来；重新生成分镜；换视频模型后单镜提示词会重写；写稿途中刷新页面，修改稿丢失、已经花的调用不退。
- **只改分镜或提示词时，完整剧情不跟着改**，两边会不一致；预览里写明了。
- **改剧情后，角色表里引用原文的证据可能对不上**——与现在一样，签发时不复查。
- **新加一句台词做不到**：要登记说话人和位置，会被拒并说明。已有台词可以改写、加长或整句删掉。
- 修改稿是同步请求，开思考的 MiMo 可能要等一两分钟。
- 演示模式下没有视频，「只改某一镜的提示词」只在测试与真实运行里能走到。

## 8. 验收证据（2026-10-11）

**A 静态**：`git diff --check` 无输出；现有提示词的 golden 测试未动、照常通过；导演助手的回复格式（`{actionKey, reply}`）不变。

**B 自动化**：`npm test` 共 2013 项，2007 通过、0 失败、6 跳过（跳过的是原本就缺真实夹具的分镜终审/修订测试）。新增 37 项：`one-sentence-edit`（17，输出结构、三类修改的执行与签发校验、作废清单、模型调用与重试）、`one-sentence-edit-server`（4，真实 HTTP：剧情 Run 三类修改各走一遍「修改稿 → 采纳」并导出导入 3.1 包；参考视频 Run 的边界签名与「相关步骤正在进行」；各种 400 / 409）、`one-sentence-edit-ui`（8）、`director-agent-progress` +4、`-controller` +2、`-server` +2。改了四处既有断言，都是本期有意的行为变化：动作清单多了修改动作、动作上限 40→80、签发校验链调用数 3→4、「重新拆分」已经拆过就先问。

在临时副本里做了 27 处反向验证，每处都有测试失败：去掉请求键白名单、基准版本核对、结果摘要核对、分镜的新媒体命名空间、「依赖与上一版相同」、相关任务在跑的 409；让角色外观可改、允许整段重写提示词、去掉提示词的必须保留项、不先校验当前版本、不换系统提示词、跳过剧情签发校验；有视频之前就给「只改提示词」、修改稿等决定时照常提议、把修改当成下一步、卡片丢了原话、卡片去重不看原话；修改稿请求带剧情副本、采纳不先问、写稿时能关弹窗、修改稿存进 sessionStorage、修改稿没处理也能生成视频；改剧情的作废清单漏了分镜；规则第 5 条退回旧写法；演示模式不对修改；「按问题修改」的默认字段被放宽；「重新拆分」只在有分镜时问。第一轮有两处没抓到，都已补上：分镜命名空间的断言写成了「新旧不相等」，新版本根本没有命名空间时也成立（改为必须带新版本号）；「把修改当成下一步」那一处变异没有生效（修改动作在算下一步之后才加），换成了有效的变异。

**C 演示模式**（4199 端口，不调模型，`runtime/demo-runs`）：剧情、分镜、单镜提示词三类修改都走了「对话栏说一句 → 卡片（带原话、改什么、作废什么、花费）→ 修改稿显示在被改的东西旁边 → 采纳 / 放弃」，导演助手各报一句、按新进度提议下一步；放弃后什么都没变；采纳后服务端的依赖与上一版相同、分镜签了新命名空间、改提示词什么都没作废；页面没有控制台错误。演示模式生成不了视频，「只改某一镜的提示词」靠给 A02 提交一条占位视频记录才走到。**当场发现并修好**：「粘贴完整故事」的 Run 里卡片说「可翻拍镜头」、修改稿和总结却说「剧情」→ 全部跟着页面叫，补了测试。
